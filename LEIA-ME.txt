ATIVAR O ENVIO DOS FORMULÁRIOS
Os campos e as interações estão implementados. Falta configurar os destinos de recebimento da VITA.
Na Vercel, configure variáveis de ambiente de servidor, sem colocá-las no JavaScript público:
VITA_FORM_OUVIDORIA_URL: endpoint HTTPS que recebe manifestações.
VITA_FORM_CANDIDATO_URL: endpoint HTTPS que recebe cadastros do banco de talentos.
VITA_FORM_FORNECEDOR_URL: endpoint HTTPS que recebe cadastros de fornecedores.
VITA_OUVIDORIA_PROTOCOLO_URL: endpoint HTTPS que consulta a validade de um protocolo.
VITA_FORM_TOKEN: token Bearer opcional para os três destinos de recebimento.
VITA_PROTOCOLO_TOKEN: token Bearer opcional específico para a consulta; usa VITA_FORM_TOKEN se ausente.

O receptor recebe POST JSON com versao:2, tipo, recebidoEm, dados e anexos.
Cada anexo contém name, type, size e data em base64. O limite total é 2 MB por envio.
RH e fornecedores aceitam um arquivo; Ouvidoria aceita até três documentos/imagens.
O destino deve responder com HTTP 2xx somente após aceitar a solicitação.
Os dados não são gravados em localStorage nem registrados em logs pelo endpoint.

A consulta do protocolo recebe POST JSON {"protocolo":"numero-informado"}.
Ela deve responder HTTP 200 com {"valido":true} somente quando o protocolo for válido.
Uma resposta com valido:false impede o avanço. Sem serviço configurado, não há validação fictícia.
No envio final, o servidor consulta o protocolo novamente antes de encaminhar a manifestação.
O site só apresenta confirmação depois do aceite do destino configurado.
Abrir o HTML localmente permite revisar o visual; o envio exige hospedagem com execução do endpoint.
